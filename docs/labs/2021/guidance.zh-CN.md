# 实验指导

## 练习难度

每项练习都会标明难度：

- 简单（Easy）：不到一小时，通常是为后续练习准备的热身。
- 中等（Moderate）：1—2 小时。
- 困难（Hard）：超过两小时。这类练习往往代码量不大，但要写对很棘手。

这些时间只是我们的粗略预估。部分可选练习连我们也没有解答，因此难度完全是猜测。如果你花费的时间超出预期，请在 Piazza 求助或到答疑时间咨询。

练习通常不需要很多代码，几十到几百行，但概念复杂，而且细节往往十分重要。因此，写任何代码前，请完成指定阅读、通读相关文件、查阅文档，例如[参考资料页](https://pdos.csail.mit.edu/6.828/2021/reference.html)上的 RISC-V 手册等。只有充分理解题目和解决方案后再开始编码。实现时分小步进行，题目通常也会建议如何拆分；每一步测试通过后再继续下一步。

提醒：不要等到截止前一晚才开始实验。将工作分散到几天内、多次进行，会高效得多。操作系统内核错误的表现可能令人困惑，需要深入思考和仔细调试才能理解并修复。

## 调试建议

以下建议有助于调试你的实现：

- 确保理解 C 和指针。Kernighan 和 Ritchie 的《C 程序设计语言》第 2 版简洁地介绍了 C。[这里](https://pdos.csail.mit.edu/6.828/2019/lec/pointers.c)有一些有用的指针练习。除非已经十分熟悉 C，否则不要跳过或草草浏览这些练习。若没有真正理解 C 指针，你会在实验中经历许多痛苦，最终不得不以艰难的方式学会。相信我们，你不会想亲自体验这种“艰难的方式”。

  特别值得记住的几个指针常见用法：

  - 如果 `int *p = (int*)100`，那么 `(int)p + 1` 与 `(int)(p + 1)` 不同：前者为 101，后者为 104。像后者那样对指针加整数时，整数会隐式乘以指针所指对象的大小。
  - `p[i]` 定义为与 `*(p+i)` 相同，引用 p 指向的内存中第 i 个对象。即使对象大于一个字节，上述指针加法规则仍使这个定义成立。
  - `&p[i]` 与 `(p+i)` 相同，得到 p 指向的内存中第 i 个对象的地址。

  大多数 C 程序不需要在指针与整数之间转换，但操作系统经常这样做。每次看到涉及内存地址的加法，都应判断它是整数加法还是指针加法，并确认被加的值是否应乘以相应大小。
- 某个练习已经部分工作时，通过提交代码保存进度。之后如果破坏了某些功能，可以退回这一检查点，再以更小的步骤前进。更多 Git 知识见 [Git 用户手册](http://www.kernel.org/pub/software/scm/git/docs/user-manual.html)，或这篇[面向计算机科学背景读者的 Git 概述](http://eagain.net/articles/git-for-computer-scientists/)。
- 测试失败时，务必理解原因。不断插入打印语句，直到弄清发生了什么。
- 打印语句可能产生大量需要搜索的输出。一种方法是在 `script` 中运行 `make qemu`，查看本机 `man script` 了解用法；它会将全部控制台输出记录到文件，供后续搜索。不要忘记退出 `script`。
- 很多情况下，打印语句已经足够，但有时单步执行汇编或检查栈上变量也很有帮助。使用 GDB 调试 xv6 时，在一个窗口运行 `make qemu-gdb`，另一个窗口运行 `gdb` 或 `riscv64-linux-gnu-gdb`，设置断点，再输入 `c`（继续），xv6 就会运行到断点。实用技巧见[使用 GNU 调试器](https://pdos.csail.mit.edu/6.828/2019/lec/gdb_slides.pdf)。
- 想查看编译器为内核生成的汇编，或某个内核地址对应的指令，可查阅 Makefile 编译内核时生成的 `kernel.asm`。Makefile 也为所有用户程序生成 `.asm` 文件。
- 内核发生 panic 时，会打印错误信息，列出崩溃时的程序计数器值。可搜索 `kernel.asm`，判断该地址属于哪个函数，也可运行 `addr2line -e kernel/kernel pc-value`，详细用法见 `man addr2line`。要获取回溯，用 GDB 重新启动：一个窗口运行 `make qemu-gdb`，另一个窗口运行 GDB 或 `riscv64-linux-gnu-gdb`，在 panic 处设置断点 `b panic`，再输入 `c`。命中断点时，输入 `bt` 获取回溯。
- 如果内核挂起，例如死锁，或无法继续执行，例如执行内核指令时发生缺页异常，可使用 GDB 查明停在哪里。一个窗口运行 `make qemu-gdb`，另一个窗口运行 GDB（`riscv64-linux-gnu-gdb`），输入 `c`。内核看起来挂起时，在 qemu-gdb 窗口按 `Ctrl-C`，输入 `bt` 获取回溯。
- QEMU 有一个 monitor，可以查询模拟机器状态。输入 `control-a c` 进入，其中 c 代表 console。`info mem` 是特别有用的命令，可打印页表。可能需要先用 `cpu` 选择所查看的核心，或用 `make CPUS=1 qemu` 启动单核 QEMU。

花时间学习上述工具是非常值得的。
